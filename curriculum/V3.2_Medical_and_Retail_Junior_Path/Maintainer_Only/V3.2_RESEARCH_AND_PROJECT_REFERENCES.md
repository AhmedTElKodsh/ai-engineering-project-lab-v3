# Research and Project Reference Registry

**Research session:** 2026-09-07. Sources were inspected during the preceding review/discussion; the pack-writing step did not rerun their code or independently validate product claims. Repository examples indicate practical architecture patterns, not a statistical ranking of day-to-day tasks or junior hiring demand. Check current APIs, licenses and activity before adapting code.

The portfolio should reproduce a real work pattern with original problem framing and measurable behavior, rather than clone a full sample. Stars, framework count and a successful demo are not substitutes for evaluation and ownership. The route emphasizes reading imperfect inputs, extracting structure, retrieving evidence, connecting tools/data and debugging failures; it does not claim a quantified frequency ordering from GitHub.

## Vacancy evidence: examples, not universal minimums

- [TKMind Consultants AI Engineer, Cairo](https://eg.linkedin.com/jobs/view/ai-engineer-at-tkmind-consultants-4373115185): reviewed example included applied LLM/RAG, tool/data work and experience/education requirements. A junior label does not guarantee zero-experience eligibility.
- [Henkel AI Engineer](https://www.henkel.com/careers/find-your-job-apply/2182732-2182732): reviewed Egypt example included Python/SQL, AI frameworks, API development and cloud/engineering skills with prior experience. It illustrates why Docker/cloud may become a targeted extension for a particular role; it does not make the full stack an onboarding gate.
- [Confer Solutions careers](https://confersolutions.ai/careers): a reviewed junior remote example was tied to India. It was used as a reminder that remote eligibility must be checked, not as an Egypt-eligible recommendation.

Listings can change or expire. Verify current vacancy content and location eligibility at application time. The curriculum does not claim to satisfy all minimum job-offer requirements; it builds evidence for a defined applied core and identifies role-specific gaps.

## Teaching rationale

[IES practice guide: Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) supports the use of worked examples interleaved with practice, spaced learning, retrieval and explanatory questions. V3.2 adapts those ideas to software work through prediction, a small worked model, learner modification, feedback and delayed transfer.

The source does not validate this exact AI curriculum or prove a single best teaching style for every learner. Product-first sequencing, chunk sizes and the two-domain transfer strategy are design choices to evaluate with the pilot. Use actual learning/engagement evidence to adjust the approach.
